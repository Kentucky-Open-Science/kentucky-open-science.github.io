About this wiki

What this site is, where its facts come from, and how to fix one.

How the wiki is built

Every night a GitHub Actions workflow asks the GitHub API for the public repositories of the {{site.org}} organization: each repository's description, topics, languages, license, activity, latest release, top contributors, and README. It writes that to a data file, regenerates every page of this site from it, and publishes the result with GitHub Pages. Nobody edits the project pages by hand.

Only public repositories are read and published. The generator requests public repositories, checks every entry again before writing it, and the site's test suite fails if anything else ever appears in the data.

Correcting a project page

Because every project page is built from the repository itself, the fix for a wrong or thin page is almost always on GitHub:

  • Missing or wrong summary: set the repository's description (the gear icon next to "About" on the repository page) and make the first paragraph of its README say what the project is.
  • Wrong research area: add GitHub topics to the repository. Areas are assigned from topics; the mapping lives in src/site.json in the site repository.
  • Anything else: open an issue in the site repository.

Changes show up after the next nightly rebuild.

About the look

The 1990s web-portal theme is intentional, and so is the plan for it: keep the look, and make it work for everyone. The scrolling marquee, the spinning globe, and the blinking badges are exactly the kind of thing that fails accessibility checks, which makes this site a useful practice target.

Accessibility

The goal is conformance with WCAG 2.1 Level AA, the technical standard adopted by the ADA Title II web accessibility rule. The site is not there yet. Every known problem is a task on the bounty board, backed by an automated test, and anyone can claim one. If you run into a barrier that is not on the board, please open an issue.
